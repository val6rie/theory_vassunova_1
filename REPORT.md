s=5, k=3, M=4, L=3, d=3, q=3, eps=1e-4


1. Принятые проектные решения
1. Расширение формата на память.
В расширенном формате добавлен блок context_models: суффиксам предыстории длины d=3 сопоставляются условные распределения, при отсутствии подходящего контекста используется default_model. Исходный формат без памяти читается без конвертации: если в файле нет context_models/memory_depth, он разбирается по старой схеме models/switches/source. Неэргодичность в текущей реализации кода не поддержана.

2. Точная рациональная арифметика.
Все вероятности, проверка нормировок и теоретические расчёты для задач 1.1 и 1.2 выполнены через fractions.Fraction. Это исключает ложные срабатывания проверки нормировки, которые даёт float при представлении долей вроде 1/3. В задаче 3 (сжатие байтов) арифметика целочисленная, Fraction не нужен.

3. Метод типов для задачи 2.
Вместо перебора 3^50 блоков применён перебор типов — векторов кратностей c1+c2+c3=n. Число типов (n+1)(n+2)/2, для n=50 это 1326. Сложность O(n^2 log n). Длина кодового слова берётся по формуле задания l(n) = floor(nR / log2(q)). Замер времени на моем пк: полный прогон до nmax=50 занимает менее 0.15 с. Точное число из замера привожу в RESULTS.md.

4. Структура контейнера zmh.
Заголовок текстово-бинарный: сигнатура ZMH1 с переводом строки, CRC32 десятичным текстом, длина исходных данных десятичным текстом, таблица частот в виде byte:count через запятую, завершающий перевод строки. Далее идёт битовый поток полезной нагрузки. Дерево Хаффмана восстанавливается из таблицы частот детерминированно.

5. Обнаружение повреждений и разграничение диагностик.
Коды возврата: 3 — не совпала сигнатура (чужой формат); 2 — повреждён или обрезан заголовок, недопустимые значения байтов и частот, сумма частот не равна длине, превышен лимит MAX_FILE_SIZE; 4 — не сошлась CRC32. Пустой файл обрабатывается отдельно: длина 0, CRC 0, таблица частот пустая.


2. Результаты измерений и анализ
1
Частотная оценка в потоке сходится к среднему по позициям внутри периода, а не к вероятности на первом такте. Причина: скользящее окно длины r с равной предельной частотой 1/L попадает на каждую из L=3 фаз переключателя. Точные значения P_start и P_avg для моего теста и таблица сходимости для N=10^2..10^6 приведены в RESULTS.md; расхождение P_avg и P_start объясняется нестационарностью по тактам при разных переключателях.

2
Энтропия стационарного источника H(X) = 1.5 бит/символ. При R = 1.6 > H(X) и eps = 1e-4 минимальное n, при котором Pe(n) <= eps, равно 41. Это согласуется с прямой теоремой Шеннона: при R > H(X) существует n0, начиная с которого Pe(n) <= eps. При R <= H(X) такого n0 нет; программа выводит это явно.

3
Числа из моего прогона --stats на пяти файлах.

text_ru.txt: H = 4.135 бит/символ, l_avg = 4.208 бит/символ, заголовок 146 байт, данные 26 байт, CR = 3.583. Разрыв l_avg - H около 0.073 бит/символ, укладывается в теоретическую границу H <= l_avg < H+1 для целочисленных длин Хаффмана. CR > 1, потому что файл маленький: заголовок 146 байт доминирует над данными 26 байт.

text_en.txt: H = 3.845, l_avg = 3.891, заголовок 121 байт, данные 27 байт, CR = 2.691. Разрыв около 0.046 бит/символ, та же причина. CR > 1 по той же причине — заголовок больше данных.

repeated.bin: H = -0.0 (ноль с точностью до знака float; фактически 0), l_avg = 1.0 бит/символ. Для одного символа Хаффман даёт код длины 1 бит, это минимально возможная длина в префиксном коде; H=0, разрыв 1 бит — теоретически допустим. Заголовок 29 байт, данные 838 байт, CR = 0.129, файл сжат примерно в 7.7 раза.

empty.bin: H = 0, l_avg = 0, заголовок 10 байт, данные 0 байт, CR не определён. Заголовок пустого файла — это ZMH1, перевод строки, два нуля и завершающий перевод строки, ровно 10 байт.

image.png: H = 7.577 бит/символ, l_avg = 7.613 бит/символ, заголовок 1965 байт, данные 64469 байт, CR = 0.981. Энтропия высокая, потому что PNG уже сжат и распределение байт близко к равномерному; выигрыш от Хаффмана минимален, разрыв l_avg - H около 0.036 бит/символ.


3. Журнал неудач

1. Наивный перебор блоков в задаче 1.2 упирался во время при n > 20. Перешла на метод типов, сложность упала с O(3^n) до O(n^2 log n).

2. float в вероятностях давал ложные ошибки нормировки в JSON на долях вроде 1/3. Перевела расчёты на Fraction.

3. В распаковщике проверка readline() на is None не работала: readline() в конце файла возвращает пустую строку, а не None. Условие заменено на not line_freq.

4. В print_stats для пустого файла стояло retur вместо return. На прогоне empty.bin это дало NameError. Опечатка исправлена, случайно удалила, оч хорошо что заметила
